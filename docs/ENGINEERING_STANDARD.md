# Инженерный стандарт семейства №2

## Границы компонентов

- `core/` владеет общими DTO, конфигурацией, LLM Gateway, хранилищем состояния и контрактами публикации.
- `modules/` содержит прикладные вычисления и строгие схемы payload. Модули используют публичные интерфейсы ядра. Ядро и соседние модули не импортируют прикладную реализацию.
- `profiles/` хранит версионируемые маппинги порталов и процессов, календари, правила эскалации и лимиты. Секреты поступают из локальной конфигурации и хранилища credentials n8n.
- `workflows/_base/` содержит переиспользуемые маршруты приёма, вызова воркеров, обработки ошибок и публикации. Проверка бизнес-данных и денежные вычисления относятся к Python.
- `ops/runners/`, `tests/core/` и `infra/` содержат соответственно эксплуатационные сценарии, тесты ядра и инфраструктуру запуска.

## Данные и переносимость

- Внешние DTO и вложенные прикладные модели используют `ConfigDict(extra="forbid")`. Схема выбирается по этапу и версии. Нехватка подтверждённых данных ведёт к `need_human=true` с кодами причин.
- В расчётах используй `Decimal` из строк. Округляй бизнес-суммы до копеек, себестоимость до восьми знаков по правилам [контрактов](contracts.md).
- On-Premise Ready означает единый OpenAI-совместимый шлюз с настраиваемыми `BASE_URL` и `API_KEY`. `FAST_LLM_MODEL` обслуживает маршрутизацию и извлечение, `SMART_LLM_MODEL` — анализ, `EMBEDDING_MODEL` — векторизацию. Для локального профиля проверяй поддержку JSON, эмбеддингов и лимитов выбранного сервера. При несовместимости индекса меняй ревизию и переиндексируй данные.
- Промпты хранятся в YAML или Markdown. Перед вызовом проверь размер входа, тайм-аут и бюджет, включая резервы на параллельные вызовы. Шлюз запрашивает JSON-объект, снимает одну внешнюю Markdown-обёртку, фильтрует неизвестные поля только в выходе модели и валидирует DTO. Публичный API отклоняет неизвестные поля.
- В технических журналах используй корреляционные ID и коды ошибок. Сведения с ограниченным доступом, URL с токенами и полные тела CRM остаются вне журналов.
- Для локального запуска используй loopback. Окружения, кэши, SQLite, состояние n8n и локальные отчёты размещай на `D:\`.

## Надёжность и приёмка

- Повтор доставки сохраняет канонический запрос. Перед CRM-записью обязательны сохранённый апрув и атомарный переход `approved → publishing`. Неопределённый результат внешней записи требует сверки.
- `transaction_telemetry` фиксирует цикл, `transaction_stages` — попытки этапов. Учитывай ошибки, фолбэки и ручную работу. Стоимость и ROI строятся по фактическим измерениям с явной долей пропусков и разделением моков, бенчмарков и пилота.
- Тесты используют подменённые LLM и CRM. Отдельно проверь дубли, конкурентный захват публикации, частичную запись, неоднозначную сверку и блокировку маршрута при эскалации.
- Бенчмарк использует размеченные входы, фиксированные версии и одинаковые наборы для парного A/B. Режимы реальных вызовов включаются явно по [регламенту](operations.md).
