# ADR-001 — гибридное ядро ai-smartflow-core

**Статус** — предложено к архитектурному ревью
**Дата** — 2026-11-20

## Решение

n8n принимает и нормализует события, связывает этапы, возобновляет маршруты и выполняет вызовы Bitrix24 через общий диспетчер. FastAPI-воркеры валидируют данные, выполняют детерминированные вычисления и обращения к LLM Gateway. Ядро Python владеет SQLite WAL, переходами состояний и аудитом. Bitrix24 владеет карточками Смарт-процессов, задачами, правами и решениями человека.

## Сквозной маршрут S1 → S2 → S3

1. n8n получает вход для S1, определяет тенанта и профиль по доверенной конфигурации, регистрирует доставку через ядро и получает канонический `request_id`.
2. Воркер S1 обрабатывает вход. n8n сохраняет проверенный результат и запрашивает публикацию. После подтверждения в Bitrix24 запись S1 становится источником для S2. Профиль указывает типы процессов, категории, стадии, поля корреляции и ссылки между карточками.
3. S2 запускается с тем же `request_id` и подтверждённой ссылкой на карточку S1. После завершения S2 тот же механизм запускает S3. Состояние `published` предыдущего этапа, успешное чтение карточки и совпадение области тенанта обязательны для передачи.
4. Если результат требует человека, n8n ставит маршрут на паузу. При необходимости профиль разрешает отдельную публикацию задачи на проверку через тот же протокол идемпотентности. Возобновление идёт по подтверждённому решению в Bitrix24 для конкретной ревизии результата.
5. S3 завершает цикл после сверки последней обязательной публикации. Повторы маршрута читают журнал и сохранённые результаты. Неподтверждённые переходы и неоднозначные записи направляются на сверку.

S1, S2 и S3 обозначают позиции маршрута. Назначение этапов, состав полей и правила апрува задаются будущими модулями и профилями. Зафиксированный результат может быть одобрен человеком или разрешён явной политикой профиля при `need_human=false`.

## Последствия

- n8n хранит состояние исполнения, ядро хранит состояние принятия и публикации. При перезапуске workflow восстанавливает маршрут из ядра.
- SQLite WAL подходит для локального размещения на одном хосте. Масштабирование писателей по хостам требует отдельного ADR для хранилища, очереди и распределённого лимитера.
- Перенос шлюза на локальные модели не меняет DTO. Доступность Bitrix24 и сетевые правила согласуются отдельно для каждого контура.
- Приёмка ядра подтверждает маршрут на заглушках, сохранение корреляции, эскалацию, повторную доставку и восстановление после частичной публикации. Интеграционные допущения подтверждаются на тестовом портале.
