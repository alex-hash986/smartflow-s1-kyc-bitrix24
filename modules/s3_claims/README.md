# S3 · Приёмка и рекламации

Проект S3.1 описан в [контрактах S3](../../docs/contracts.md#контракты-модуля-s3_claims-кейс-s3).

```text
modules/s3_claims/
├── README.md
├── module.py
├── contracts.py
├── parser.py
├── matcher.py
├── scoring.py
├── publication.py
└── prompts/
    └── extract_acceptance.yaml
```

| Файл | Ответственность |
| --- | --- |
| `README.md` | Границы этапа и карта файлов |
| `module.py` | Точка входа BaseSmartWorker, вызовы прикладных операций через интерфейсы ядра |
| `contracts.py` | Строгие Pydantic v2 DTO, перечисления, коды эскалации и правила точности |
| `parser.py` | Извлечение TEXT/PDF, нормализация и контроль арифметики. Резервирование и чтение кэша через ядро |
| `matcher.py` | 3-Way Match, подтверждение связи акта с первичным документом, детализация расхождений |
| `scoring.py` | Расчёты Decimal, допуски, пени, претензия, исход и Markdown-отчёт |
| `publication.py` | Проверка решения, привязка очереди и создание команды публикации |
| `prompts/extract_acceptance.yaml` | Схема извлечения для FAST LLM, версия `1`, вариант `baseline` при первой реализации |

SQLite, HTTP-адаптеры и диспетчер публикаций принадлежат ядру. `publication.py` связывает результаты S3 с журналом диспетчера. Маршруты активируются профилем с `s3_claims.enabled: true` и полными привязками портала. Профиль ограничивает объём текста, размер PDF и число страниц (`extraction.max_pdf_pages`, по умолчанию 100).

Для новых расчётов S2 ядро хранит утверждённые строки победителя в `s2_award_items` вместе с номером попытки. Для присуждения без подтверждённых строк шлюз возвращает `S3_AWARD_UNCONFIRMED`.

Подтверждённые условия пени передаёт доверенный адаптер договора через `S3Worker.record_penalty_terms`. Адаптер проверяет источник, базу от утверждённого итога S2 и ставки сделки. Метод фиксирует ссылку на доказательство и хэш присуждения. Ставки профиля задают поддерживаемый шаблон. При просрочке без подтверждённых совпадающих условий S3 возвращает `S3_PENALTY_TERMS_UNCONFIRMED`.

Если извлечение прервалось с неопределённым расходом, запись остаётся зарезервированной. После подтверждения остановки прежнего исполнителя и сверки расхода оператор закрывает запись через `S3Worker.reconcile_interrupted_parse`, передавая ссылку на подтверждение. Повтор исходного вызова затем возвращает сохранённый результат с эскалацией. Для повторной обработки регистрируется исправленный пакет.
