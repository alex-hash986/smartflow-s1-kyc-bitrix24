# S1 · AI-проверка и онбординг контрагента

Нормативная спецификация в [контрактах S1](../../docs/contracts.md#контракты-модуля-s1_kyc-кейс-s1). Модуль содержит извлечение реквизитов и оценку ЮЛ и ИП.

```text
modules/s1_kyc/
├── README.md
├── module.py
├── contracts.py
├── requisites.py
├── parser.py
├── scoring.py
└── prompts/
    └── extract_requisites.yaml
```

| Файл | Ответственность |
| --- | --- |
| `module.py` | Адаптер `BaseSmartWorker` для оценки. Привязка схем оценки к конвертам ядра и сбор телеметрии |
| `contracts.py` | DTO извлечения, снимка и оценки. Строгая валидация, согласованность идентификаторов и результата |
| `requisites.py` | Нормализация и проверка формата реквизитов и контрольных цифр |
| `parser.py` | Проверка источника, извлечение из текста или PDF через FAST LLM, проверка результата и причины эскалации |
| `scoring.py` | Чистый расчёт по профилю, стоп-факторы, условия оплаты и детерминированное досье |
| `prompts/extract_requisites.yaml` | Версия, вариант и шаблон извлечения с JSON-выходом |

n8n оркестрирует извлечение и запросы реестров. Запись в Bitrix24 проходит через общий диспетчер ядра. Профили в [default_b2b](../../profiles/default_b2b/profile.yaml) и [construction_supply](../../profiles/construction_supply/profile.yaml) задают самостоятельные наборы правил.


FastAPI поднимает сервис на `127.0.0.1:8021`. После регистрации доставки
`POST /s1/parse` извлекает реквизиты, а `POST /s1/evaluate` оценивает
переданный снимок реестров через тот же воркер и журнал, что и
`POST /v1/workers/S1/run`. Оба маршрута требуют сервисный токен.
YAML-шаблоны пригодны для расчёта. Привязки полей портала заполняются на S1.3.
