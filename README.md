# Smartflow · Проверка контрагентов и AI-тендеры в Bitrix24

`smartflow-s1-kyc-bitrix24` содержит модули `s1_kyc` и `s2_tender` и общее ядро `ai-smartflow-core`. S1 извлекает реквизиты ЮЛ и ИП из текста и PDF, проверяет контрольные цифры, оценивает подтверждённый снимок реестров и рассчитывает рекомендуемый лимит. Результат и досье публикуются в Смарт-процессе Bitrix24. Заявки с недостаточными данными или стоп-факторами передаются службе безопасности.

S2 проверяет подтверждённый допуск поставщиков, извлекает и сопоставляет позиции КП, рассчитывает рейтинг и формирует конкурентную карту. Ответственный утверждает победителя или отмену в той же карточке Bitrix24.

## Архитектура

| Компонент | Назначение |
| --- | --- |
| n8n | Принимает заявку, вызывает API извлечения и оценки, передаёт разрешённую публикацию диспетчеру. В комплекте есть workflow с учебными реестрами. |
| FastAPI и Pydantic v2 | Проверяют входные данные, выполняют скоринг и формируют досье. Строгие DTO отклоняют лишние поля через `extra="forbid"`. |
| SQLite WAL | Хранит ключи доставки, попытки, телеметрию и шаги публикации. |
| Смарт-процессы Bitrix24 | Хранят карточки, утверждённые лимиты, досье в таймлайне и очередь ручной проверки. |

- **Точные расчёты.** Скоринг и денежные операции используют `Decimal` с `ROUND_HALF_UP`.
- **Идемпотентность и восстановление.** Повтор доставки получает исходный идентификатор заявки. Диспетчер атомарно захватывает публикацию по переходу `approved → publishing`. Подтверждённая запись переводится в `published`, неопределённый результат — в `reconcile` для сверки.
- **Бюджет LLM.** Шлюз использует тарифы `LLM_MODEL_RATES` и проверяет лимит `MAX_CYCLE_COST_RUB` перед запросом. FAST LLM дополняет неполный читаемый текст, оценка риска выполняется детерминированно.
- **Ограничение REST.** Диспетчер выдерживает до двух запросов в секунду на портал (`≤ 2 req/sec`).

## Результаты приёмки S1

Benchmark включал **70 циклов** — одинаковые 35 размеченных синтетических заявок на каждый профиль с подменёнными LLM и реестрами. Диапазон p95 составляет около **521–536 мс** в этом окружении.

| Метрика | `default_b2b` | `construction_supply` |
| --- | ---: | ---: |
| Автоодобрение | 20/35 · 57,1% | 12/35 · 34,3% |
| Эскалации | 15/35 · 42,9% | 23/35 · 65,7% |
| Время цикла p95 | 535,85 мс | 521,66 мс |
| Стоп-факторы TP / FP / FN | 5 / 0 / 0 | 5 / 0 / 0 |
| Детерминированные циклы с нулевой стоимостью токенов | 30/30 | 30/30 |

На живом тестовом портале Bitrix24 (`entityTypeId=1040`) проверены две публикации с синтетическими входами. Одобренная карточка прошла проверку допуска к S2. Повтор доставки сохранил одну карточку и один комментарий. Заявка с банкротством и недостоверным адресом получила `CRITICAL`, рекомендацию нулевого лимита и досье в очереди СБ. Workflow n8n проверены отдельно в офлайн-контуре.

[Паспорт S1](docs/passport.md) содержит методику, результаты и сценарную экономику. [Интерактивная презентация](docs/presentation/index.html) открывается локально в браузере и включает калькулятор окупаемости.

## Результаты приёмки S2

На 35 одинаковых синтетических тендерах базовый профиль рекомендовал победителя в 30 случаях, профиль стройпоставок — в 20. Остальные тендеры направлены на проверку. В обоих профилях выявлены 10/10 недопущенных поставщиков и 5/5 арифметических ошибок без ложных срабатываний.

Смарт-процесс «Тендер и свод КП» принял присуждение и отмену на живом тестовом портале (`entityTypeId=1044`, `categoryId=17`). `portal_b24_b2b` использует ревизию `4`. Повтор сохранил прежние карточки и по одному комментарию на шаг публикации.

[Паспорт S2](docs/passport_s2.md) описывает методику, фактические результаты и сценарную экономику. [Презентация S2](docs/presentation/s2.html) включает конкурентные карты и калькулятор.

| --- | --- |
| S1 | `POST /v1/deliveries`, `POST /s1/parse`, `POST /s1/evaluate`, `POST /s1/publication/prepare` |

## Структура репозитория

| Каталог | Содержимое |
| --- | --- |
| `core/` | API, журнал SQLite, шлюз LLM, клиент Bitrix24 и диспетчер |
| `modules/s1_kyc/` | DTO, проверка реквизитов, извлечение и скоринг |
| `modules/s2_tender/` | Парсинг КП, допуск по S1, сопоставление, скоринг и публикация |
| `profiles/` | Пороговые правила, политики эскалации и привязки портала |
| `workflows/`, `infra/` | Экспорты n8n и Compose |
| `ops/runners/` | Синтетический датасет, benchmark и утилиты тестового портала |
| `tests/`, `docs/` | Проверки, контракты, регламент и результаты приёмки |

## Запуск и проверки

Требуются Python 3.11+ и активированное виртуальное окружение. Для локального API скопируйте [.env.example](.env.example) в `.env`, задайте `WORKER_TOKEN` и укажите доступный локальный каталог для SQLite и кэшей. Для подключения своего тестового портала настройте профиль и `BITRIX24_WEBHOOK_URL` по [регламенту](docs/operations.md).

```bash
python -m pip install -e ".[dev]"
pytest
ruff check .
mypy . --strict
python -m uvicorn core.api:app_factory --factory --host 127.0.0.1 --port 8021
```

Результаты актуального прогона проверок указаны в [срезе состояния](docs/status.md).
